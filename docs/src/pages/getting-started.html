Guide

Getting Started

Bascik requires Node.js v24+. Get up and running in under five minutes.

Installation

Install Bascik with your preferred package manager:

yarn add @bascik/bascik # or npm install @bascik/bascik # or pnpm add @bascik/bascik

Project Setup

Add the Bascik scripts to your package.json:

{ "scripts": { "dev": "bascik", "build": "bascik --build" } }

Folder Structure

Bascik looks for two directories by default. Both can be overridden in bascik.config.js.

src/ components/ ← component .html and .css files pages/ ← one .html file per route

Custom 404 Page

If you create a 404.html file in your pages directory (e.g. src/pages/404.html), Bascik's built-in development server will automatically serve it as a fallback for any non-existent routes with a 404 status code.

When you build your site for production (bascik --build), this file is compiled to dist/404.html, which is the standard location recognized by most static hosting providers (such as GitHub Pages, Netlify, Vercel, and Cloudflare Pages) to serve custom 404 pages.

Your First Component

1

Create the component file

The file name becomes the tag name.

<nav class="nav"> <a href="/">Home</a> <a href="/about">About</a> </nav>
2

Reference it in a page

No imports or registration. Just use the tag.

<!DOCTYPE html> <html> <head><title>Home</title></head> <body> <site-nav></site-nav> <h1>Hello world</h1> </body> </html>
3

Start the dev server

yarn dev

The server runs on https://localhost:8443 and live-reloads on every change.

4

Build for production

yarn build

Output is written to the dist/ directory. Deploy it anywhere that serves static files.

Next: Add scoped CSS to your component by creating src/components/site-nav/site-nav.css alongside your HTML file. See Scoped Styles →

CLI & Development Workflow

Bascik's command-line interface is designed to provide clean, minimal, and informative terminal output. Here is a guide on what you will see in your terminal during development.

Starting the Dev Server

When you start the dev server via yarn dev (or bascik), Bascik automatically generates local SSL/TLS certificates for its built-in HTTP/2 server, transpiles all pages inside your pages directory, and begins watching for changes:

Generated self-signed certificate for the development server Server running at https://localhost:8443 transpiled: pages/getting-started.html transpiled: pages/index.html transpiled: pages/about.html ✓ 3 pages transpiled in 45ms

Watching for File Changes

While the dev server is active, Bascik watches your file system and incrementally updates your build as files are added, updated, or removed.

  • Modifying/Adding Pages: Editing or adding an HTML page in your pages directory (e.g. src/pages/about.html) triggers incremental transpilation of just that page: transpiled: pages/about.html
  • Modifying Components: Editing a component (e.g. src/components/site-nav/site-nav.html) triggers selective transpilation. Bascik tracks dependency mappings and only rebuilds pages that actually reference that component: transpiled: pages/index.html transpiled: pages/about.html
  • Static Assets: Replicating any non-HTML static assets (like custom CSS, JS files, or images) from pages directly into the output directory: copied: /Users/collin/github/bascik/docs/src/pages/css/custom.css
  • Deleting Pages: Removing a page from your pages directory automatically cleans up its compiled output counterpart to prevent dead files: deleted file: /Users/collin/github/bascik/docs/src/pages/old-page.html

Transpilation & Build Errors

If you introduce a syntax mistake or a runtime error inside a custom build script, Bascik prevents the server from crashing, gracefully logs a descriptive error with the file and exact line/column location, and continues running.

  • Component Transpilation Failure: If a component markup or CSS scoping parser fails during transpilation: [bascik] Transpilation failed for component <site-nav> during css-scoping in "pages/about.html" at (line 22, column 8) Defined in component template: "components/site-nav/site-nav.html" Error: ParseError: CSS Selector is invalid or could not be parsed.
  • Build Script Failure: If a build-time JavaScript execution block (using <script data-bascik-build>) encounters an error: [bascik] build script error in "pages/index.html" at (line 12, column 5): ReferenceError: marked is not defined

Scoped Styles (Quick Intro)

Pair a .css file with your component HTML by using the same name in the same directory:

src/components/ site-nav/ site-nav.html ← component markup site-nav.css ← scoped styles

Class names in the CSS are automatically prefixed per component instance at build time.
