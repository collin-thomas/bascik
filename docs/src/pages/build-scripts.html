Build-time Scripts

Build-time scripts let you run Node.js code at transpile time and inject the output directly into the page — no client-side JavaScript required. Use them to pull in Markdown files, generate navigation from JSON, or fetch remote data at build time.

Live Build Script Example

The card below was generated by a build script that read a Markdown file from the content/ folder and passed it to a component.

<script data-bascik-build> import { readFile } from 'node:fs/promises'; import { marked } from 'marked'; const md = await readFile('./content/01-overview.md', 'utf8'); const firstPara = md.split('\n\n')[1]; console.log(` <feature-card data-bascik-prop-label="Build Time" data-bascik-prop-title="Generated from Markdown" data-bascik-prop-desc="${marked.parseInline(firstPara)}"> </feature-card> `); </script>

Your Node.js Project

A Bascik project is a Node.js project. That means everything available in the npm ecosystem is available in your build scripts — install a package with npm install (or your package manager of choice) and import it directly.

You are not limited to what Bascik provides. Your build scripts can call databases, run shell commands, talk to APIs, parse structured files, generate images, or do anything else a Node.js script can do. The output is captured from stdout and injected into the page.

Using npm Packages

Install a package once and import it anywhere across your build scripts:

npm install gray-matter <script data-bascik-build> import { readFile } from 'node:fs/promises'; import matter from 'gray-matter'; const raw = await readFile('./content/post.md', 'utf8'); const { data, content } = matter(raw); console.log(` <article> <h1>${data.title}</h1> <p class="date">${data.date}</p> </article> `); </script>

Shared Utility Modules

Build scripts are just ESM modules. You can write your own utilities and import them across multiple pages or components — no special Bascik API required:

// src/lib/render-cards.js import { readFile } from 'node:fs/promises'; export async function renderCards(jsonPath) { const items = JSON.parse(await readFile(jsonPath, 'utf8')); return items.map(item => ` <div class="card"> <h3>${item.title}</h3> <p>${item.description}</p> </div> `).join('\n'); } <script data-bascik-build> import { join } from 'node:path'; import { pathToFileURL } from 'node:url'; import { renderCards } from pathToFileURL(join(process.cwd(), 'src/lib/render-cards.js')).href; console.log(await renderCards('./content/team.json')); </script>

Import paths in build scripts: Node.js requires absolute paths or full URLs when importing local modules from a dynamically executed script. Use pathToFileURL(join(process.cwd(), 'relative/path.js')).href to import your own modules reliably from any build script.

Environment Variables

Environment variables set in your shell or a .env file (loaded with a tool like dotenv) are accessible in build scripts via process.env. Use this to inject API keys, deployment URLs, or feature flags at build time without shipping them to the browser:

<script data-bascik-build> const apiUrl = process.env.API_URL ?? 'https://api.example.com'; console.log(`<meta name="api-url" content="${apiUrl}" />`); </script>

Limitations

  • No streaming output — the full stdout of the script is collected before injection. You cannot stream HTML into the page incrementally.
  • No HMR awareness — in dev mode Bascik watches source files. If a build script reads an external file (e.g. a Markdown file), changes to that file won't automatically re-trigger the script. Restart the dev server to re-run.
  • ESM only — scripts are written as .mjs files. Use import syntax; require() is not available.
  • Node.js packages only — scripts execute in Node.js, not the browser. Browser globals like window and document are not available.
